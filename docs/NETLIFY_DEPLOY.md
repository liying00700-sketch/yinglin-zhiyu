# Netlify 部署步骤

## 1. 部署前准备

1. 将 `yinglin-child-growth` 作为一个独立 Git 仓库，或在现有仓库中保留为独立子目录。
2. 先准备可公网访问的育儿问答 API，接口需要接受 `POST /api/parenting/ai` 的现有萤林问答契约。
3. 问答 API 内部必须继续执行资料准入、版权状态检查和安全边界；不要把原始书籍或模型密钥放到本项目的前端环境变量中。

## 2. 在 Netlify 创建站点

1. 登录 Netlify，选择从 Git 导入项目。
2. 如果 `yinglin-child-growth` 是仓库子目录，将 **Base directory** 设置为 `yinglin-child-growth`；如果它本身就是独立仓库，Base directory 留空。
3. 构建参数已写入 `netlify.toml`：
   - Build command：`pnpm run build`
   - Publish directory：`dist`
   - Node.js：22
4. 触发第一次部署。此时静态页面可用，但未配置 API 时，育儿问答会明确提示服务尚未配置。

## 3. 配置育儿问答

在站点的环境变量设置中添加：

| 变量 | 是否必填 | 说明 |
|---|---|---|
| `PARENTING_API_URL` | 是 | 完整上游地址，例如 `https://api.example.com/api/parenting/ai` |
| `PARENTING_API_TOKEN` | 否 | 上游需要 Bearer Token 时填写；只保存在 Netlify 服务端 |

保存变量后重新部署。前端请求 `/api/parenting/ai`，由 `netlify/functions/parenting-ai.mjs` 同站转发，避免在浏览器暴露上游 Token。

## 4. 发布前验收

1. 未设置孩子档案时，问答应先引导设置出生日期。
2. 普通问题应依次经过：描述问题 → 补充持续时间、频率和已尝试方法 → 安全确认 → 结构化回答。
3. 勾选任一红旗信号时，不应请求模型，应直接显示急救／就医提示。
4. 上游不可用时，只显示错误和重试入口，不出现预设答案。
5. 回答应包含：判断边界、2—3个信号、一个最小行动、可直接说的话、观察点和升级条件。
6. 只展示已准入资料的名称和类型，不显示原文件路径、下载链接或长段原文。
7. 刷新页面后，孩子档案、问答历史、有效方法、计划和观察应仍保留在当前浏览器。
8. 用手机宽度检查底部五个入口无横向溢出，孩子档案从右上角进入。

## 5. 当前生产边界

- Netlify Function 只是安全转发层，不包含模型密钥、资料库或资料准入逻辑；这些仍属于上游问答服务。
- 当前家庭数据保存在 `localStorage`，不具备账号、家庭隔离、跨设备同步、导出删除和审计能力。
- 上线为正式会员产品前，需要把家庭数据迁移到有访问控制的服务端存储，并完成隐私政策、数据删除与审计流程。
